# Общее
Сейчас в системе много путаницы, поэтому система мониторинга в особенности логи позволят хоть как-то разобраться в это продукте.
Следует покрыть логами следующие системы:
1. CRM/MES API
2. RabbitMQ
3. База данных

Уровни логирования:
1. Использовать логи уровня INFO для общей информации о бизнес событиях (заказ создан, отправлен, получен и т.д.)
2. warn если есть странное поведение в системе (долгий расчет, либо данные расходятся логически)
3. ERROR когда произошла ошибка, операции прекращена (таймаут запроса, ошибка база данных и т.д.)

Логи из разных систем:
MES API:
1. Начался\закончился расчет стоимости
2. Статус заказа изменился
3. Заказ отправлен покупателю

CRM API:
1. Заказ доставлен в MES
2. Заказ создан
3. Менеджер изменил статус заказа

RabbitMQ:
1. Сообщение опубликовано
2. Сообщение получено
3. Сообщение ушло в DLQ или retry

# Мотивация
1. Поддержка сможет быстрее отвечать клиентам на их жалобы и обращения связанные, что произошло когда нажал кнопку и т.д.
2. Разработчики будут быстрее находить ошибки и понимать их причину

Метрики:
1. Среднее время расследование инцидентов
2. Кол-во обращений к поддержке и разработчикам
3. Кол-во потерянных заказов

Приоритет реализации:
1. MES API ключевая система которая рассчитывает стоимость, с которой работают операторы и внешние клиенты
2. RabbitMQ - через очередь могут теряться и зависать сообщения
3. CRM API подтверждение заказов и управление ими

# Предлагаемое решение
Внедрить централизованное логирование. Лоли должны отправляться в json со всех сервисов и быть доступным для просмотра в одном месте
Например использовать такое решение как ELK
MES/CRM API, RabbitMQ, DB -> json log -> log collector (filebeat) -> log processing (logstash) -> log storage (elastic search) -> log ui (kibana)

Безопасность:
1. Надо добавить фильтрацию на чувствительную информацию (пароли, токены, телефоны, в особенности перс. данные)
2. Доступ должен быть ограничен на такие роли как: разработчики (логи приложений), dev ops (логи инфраструктуры), поддержка (фильтрация только order_id например), продукт (только дешборды)
3. Доступ через корпоративный VPN

Хранить логи:
1. Production 2 месяца
2. Dev - 7 дней
3. Security - 1 год

Хранить в отдельных индексах по окружению и сервису, например prod-crm-api, prod-mes-api и т.д.

Стоит так же добавить алертинг
1. Резкий рост error логов
2. Более 5 сообщений в DLQ
3. 500 ошибки внешнего API

Так же стоит смотреть за аномалиями когда нагрузка вырастает кратно на систему без какой, либо причины (мероприятие, крупный клиент и т.д.)
